Project Objectives & Outcomes

Syllabus Alignment & AI Competencies
  • 1. Symbolic Knowledge Representation: Model real-world recipes and dietary rules using nested list structures without relational databases or external dependencies.
  • 2. Pure List Processing: Implement set intersection, set difference, and membership search using recursive CAR/CDR/CONS paradigms.
  • 3. Rule-Based Substitution Inference: Design an expert association system capable of evaluating alternative ingredients (e.g. olive oil for butter, tofu for paneer).
  • 4. Multi-Constraint Filtering: Combine dietary preference predicates with time-bounded threshold sorting.
  • 5. Heterogeneous System Integration: Interface a Common Lisp (SBCL) symbolic core with a modern Python/Flask web microservice.

Viva Voce Preparation Guide (Top 10 Questions)

Essential questions that examiners ask during project evaluation, complete with precise academic answers.

LISP (LISt Processing), developed by John McCarthy in 1958, was designed specifically for symbolic AI. Unlike procedural languages that prioritize arithmetic on numbers, LISP treats lists and symbols as first-class citizens. Its features include Homoiconicity (code and data have the identical representation), built-in automatic garbage collection, dynamic typing, and natural tree traversal, making it ideal for rule-based systems, expert systems, and automated theorem provers.

CAR stands for "Contents of the Address part of Register" and CDR stands for "Contents of the Decrement part of Register". These names originated from the hardware architecture of the IBM 704 vacuum-tube computer on which McCarthy first implemented Lisp.

In modern computer science:
• CAR returns the head (first element) of a list: (car '(a b c)) → a.
• CDR returns the tail (remainder) of a list: (cdr '(a b c)) → '(b c).

In pure functional list processing, loops are replaced by structural induction over lists. A recursive list function typically defines two cases:
1. Base Case: Test if the list is empty using (null lst). If so, return a terminal value (e.g., 0 or NIL).
2. Recursive Step: Process the head element using (car lst), and make a recursive call on the tail (cdr lst).
This guarantees mathematical immutability and avoids side effects caused by mutable loop counter variables.

Missing ingredients are computed as the relative set difference between the recipe's required ingredients list \(R\) and the user's available pantry list \(U\): \[ M = R \setminus U = \{ x \in R \mid x \notin U \} \] In list processing, missing-ingredients traverses \(R\). If (member (car R) U) is true, the item is skipped; if false, it is constructed into the missing list via (cons (car R) (missing-ingredients (cdr R) U)).

The substitution engine maintains an Association List (A-List) of dotted pairs: '((olive-oil . butter) (tofu . paneer) ...). When checking if an ingredient is present, the function has-ingredient-or-substitute-p first checks for a direct match. If not found, it recursively searches the substitution table to find acceptable alternatives. If the user owns an alternative, it records a match while tagging a substitution flag.

• S-Expression (Symbolic Expression): The universal syntax of Lisp. Either an atom (symbol, number) or a pair/list constructed from cons cells.
• Association List (A-List): A list of pairs where each element is a cons cell (key . value), accessed via ASSOC.
• Property List (P-List): A flat list with alternating key indicators and values (:name "Pasta" :diet 'veg), accessed via GETF.

Let \(K\) be total recipes in the knowledge base, \(M\) be the average number of ingredients per recipe, and \(N\) be the number of user ingredients:
• Evaluating one recipe takes \(\mathcal{O}(M \times (N + S))\) where \(S\) is substitution rules count.
• Evaluating all \(K\) recipes takes \(\mathcal{O}(K \cdot M \cdot N)\).
• Sorting the qualified recipes takes \(\mathcal{O}(K \log K)\).
Total time complexity is \(\mathcal{O}(K \cdot M \cdot N + K \log K)\), running in under 15ms for our knowledge base!

The module engine_fallback.py defines primitive helper functions car(lst), cdr(lst), cons(x, lst), and null(lst). Rather than relying on Python set operations (e.g., set.intersection), the algorithm follows the exact same recursive induction and structure as lisp/recipes.lisp. This ensures that even without SBCL installed, the system faithfully demonstrates list processing principles.

A Higher-Order Function is a function that takes other functions as arguments or returns a function. In this project:
• MAPCAR applies evaluate-recipe to every recipe in the knowledge base.
• REMOVE-IF-NOT acts as a functional filter accepting lambda predicates for dietary and time constraints.
• SORT accepts a binary comparator lambda function to order recipes by heuristic score.

When SBCL is installed, Flask's Python backend spawns an external process using subprocess.run() invoking sbcl --script lisp/recipes.lisp [diet] [max-time] [ingredients...]. The Lisp script compiles and executes the symbolic inference and outputs a serialized JSON structure to standard output, which Flask parses and returns to the frontend via POST /api/suggest.
